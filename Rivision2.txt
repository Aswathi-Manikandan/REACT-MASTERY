List in React:

    In React, a list means displaying multiple similar items from an array.

    For example, if we have:

    const users = ["Aswathi", "Anu", "Rahul"];

    We may want to display:

    Aswathi
    Anu
    Rahul

    Instead of writing each <li> manually, React commonly uses map()

creating a list : 
    function App() {
    const users = ["Aswathi", "Anu", "Rahul"];

    return (
        <ul>
        {users.map((user) => (
            <li>{user}</li>
        ))}
        </ul>
    );
    }

    Here:

    users → array
    map() → goes through each item
    <li>  → creates UI for each item

2. Why do we need key?

    When rendering lists, React expects each item to have a unique key.

    function App() {
    const users = [
        { id: 1, name: "Aswathi" },
        { id: 2, name: "Anu" },
        { id: 3, name: "Rahul" }
    ];

    return (
        <ul>
        {users.map((user) => (
            <li key={user.id}>{user.name}</li>
        ))}
        </ul>
    );
    }

    Here:

    key={user.id}

    helps React identify each list item between renders.

    This is especially useful when items are added, removed, or reordered.

3. Why not use index as key?

    You can technically do:

    users.map((user, index) => (
    <li key={index}>{user}</li>
    ))

    But using a stable unique ID is generally better when available.

    Why?

    Suppose:

    Before:
    A
    B
    C

    Then A is removed:

    B
    C

    The indexes change:

    B → 0
    C → 1

    With stable IDs, React can correctly understand which items are actually the same.

CSR vs SSR in React : 
                            CSR	                                        SSR
        Rendering happens mainly in browser	                    HTML is generated on server
        Initial page may require JS before content appears	    Server can send rendered HTML
        Common for SPAs	                                        Common for SEO/content-heavy applications
        Server sends application resources	                    Server generates HTML for the request
        Browser does more rendering work	                    Server does more rendering work

What is an SPA? :
    A Single Page Application is a web application where the browser initially loads one main HTML page, and
    then JavaScript/React updates the content as the user navigates without doing a full page reload for every route.

What is React Router? :
    React Router is a library used to handle navigation and routing in React applications.

BrowserRouter
    <BrowserRouter>
    It provides the routing context to the React application and uses the browser's URL/history APIs for navigation.

Routes
    <Routes>
    It contains the application's route definitions.

Route
    <Route path="/products" element={<Products />} />
    It basically says:
    When the URL matches /products, render the Products component

Navigation with Link:

    Instead of using a normal anchor:
    <a href="/products">Products</a>

    React Router provides:

    import { Link } from "react-router-dom";

    <Link to="/products">Products</Link>

    Link is designed for client-side navigation in a React Router application.

What is Outlet?:
    Outlet is a component provided by React Router that acts as a placeholder 
    where a child route's component will be rendered.

Outlet vs Route :
    Route defines which component should render for a path.

    <Route path="profile" element={<Profile />} />

    Outlet defines where that child component should appear inside the parent.

    <Outlet />

    So:

    Route   → What should render?
    Outlet  → Where should the child render?
