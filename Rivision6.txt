JSX in React :
    JSX = JavaScript XML.

    JSX allows us to write HTML-like syntax inside JavaScript.

    For example:

    function App() {
    return <h1>Hello Aswathi</h1>;
    }

    Here:

    <h1>Hello Aswathi</h1>

    looks like HTML, but inside a React component it is JSX.

    The main benefit is that we can write UI structure and JavaScript logic together.

    2. Why do we use JSX?

    Without JSX:

    const element = React.createElement(
    "h1",
    null,
    "Hello Aswathi"
    );

    With JSX:

    const element = <h1>Hello Aswathi</h1>;

    JSX makes React code easier to read and write.

3. JavaScript inside JSX

    We can put JavaScript expressions inside {}.

    function App() {
    const name = "Aswathi";

    return <h1>Hello {name}</h1>;
    }

    Output:

    Hello Aswathi

    You can use expressions:

    <h1>{10 + 20}</h1>

    Output:

    30

    But statements such as if cannot directly be written inside {}:

    // ❌
    <h1>{if (age > 18)}</h1>

    Instead, use conditional rendering techniques such as ternary:

    <h1>{age >= 18 ? "Adult" : "Minor"}</h1>
4. JSX attributes

    JSX uses attributes similar to HTML, but some names are different because JSX 
    follows JavaScript naming conventions.

    <button className="btn">Click</button>

    HTML:

    <button class="btn">Click</button>

    Common examples:

    class      → className
    for        → htmlFor
    onclick    → onClick
    tabindex   → tabIndex
5. JSX must return one parent

    This:

    return (
    <h1>Hello</h1>
    <p>Welcome</p>
    );

    ❌ is not valid because there are two adjacent elements.

    Use a parent:

    return (
    <div>
        <h1>Hello</h1>
        <p>Welcome</p>
    </div>
    );

    Or use a Fragment:

    return (
    <>
        <h1>Hello</h1>
        <p>Welcome</p>
    </>
    );
6. JSX is not HTML

    This is an important interview point.

    JSX looks like HTML, but it is actually syntax used to describe React elements.

    Conceptually:

    <h1>Hello</h1>

    is transformed into something like:

    React.createElement("h1", null, "Hello");

    Modern React projects usually use the automatic JSX transform, so you normally don't 
    write React.createElement() yourself.


React Fiber :
    React Fiber is React's internal reconciliation architecture introduced to make rendering work more 
    flexible and efficient. It represents units of work as Fiber nodes and allows React to prioritize, 
    pause, resume, and process rendering work. Fiber is also the foundation that enables React's modern 
    concurrent rendering capabilities.


Babel :
    babel is a JavaScript compiler/toolchain that transforms modern JavaScript and JSX code into JavaScript 
    that can be understood and executed by the target environment. In React applications, Babel is 
    commonly used to transform JSX into JavaScript and can also transform newer JavaScript syntax 
    when configured with the appropriate presets or plugins.

Simple understanding :

    You write React code like:

    function App() {
    return <h1>Hello</h1>;
    }

    The browser doesn't directly understand JSX syntax.

    Babel can transform the JSX into JavaScript, conceptually like:

    React.createElement("h1", null, "Hello");

    Then React can use that to create the UI.

    So the basic flow is:

    You write JSX
        ↓
    Babel
        ↓
    JavaScript
        ↓
    React
        ↓
    UI
    Babel is not React

    This is important:

    React → library for building UI
    Babel → tool that transforms code

    Babel doesn't create your UI. It transforms your source code.

3. What can Babel do? :

    Babel can transform things such as:

    JSX

    <h1>Hello</h1>

    into JavaScript.

    It can also transform newer JavaScript syntax depending on the configured presets/plugins.

    For example:

    const add = (a, b) => a + b;

    can be transformed for environments that don't support that syntax.

4. Babel and JSX :

    When learning React, remember:

    JSX
    ↓
    Babel / JSX transform
    ↓
    JavaScript
    ↓
    React creates elements

    One modern detail: React projects today often use the automatic JSX transform, 
    so the generated code doesn't necessarily literally call React.createElement() in the 
    source you see. The important idea is that JSX is transformed into JavaScript that React can process.


Transpiler :
    A transpiler is a tool that converts source code from one version or syntax of a programming 
    language into another version or syntax of the same or closely related language. For example, 
    Babel can transpile modern JavaScript and JSX into JavaScript syntax that is compatible 
    with the target environment.

Webpack :
    Webpack is a module bundler that analyzes the dependencies of a web application and 
    bundles JavaScript, CSS, images, and other assets into files that can be served to the 
    browser. It can also use loaders and plugins to transform and process different types of files.
