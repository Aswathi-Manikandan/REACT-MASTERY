Event Handling :
    Event handling in React is the process of responding to user interactions such as clicks,
    typing, submitting forms, and mouse or keyboard actions. React uses event handlers such 
    as onClick, onChange, and onSubmit, where we pass a function that executes when 
    the event occurs. React provides a SyntheticEvent object to the event handler.

When a user interacts with a webpage, an event happens.

    Examples:

    Click a button       → click event
    Type in an input     → change/input event
    Submit a form        → submit event
    Press a keyboard key → keyboard event
    Move the mouse       → mouse event

    In React, we tell the element which function should run when that event happens.

    Example
    function App() {
    function handleClick() {
        console.log("Button clicked");
    }

    return (
        <button onClick={handleClick}>
        Click Me
        </button>
    );
    }

    Flow:

    User clicks button
        ↓
    onClick event occurs
        ↓
    handleClick() runs
        ↓
    "Button clicked"

Common React events :
                     Event	                           Used for
                    onClick	                        Clicking
                    onChange	                    Input value changes
                    onSubmit	                    Form submission
                    onFocus	                        Input gets focus
                    onBlur	                        Input loses focus
                    onMouseEnter	                Mouse enters element
                    onMouseLeave	                Mouse leaves element
                    onKeyDown	                    Key is pressed
                    onKeyUp	                        Key is released

Passing a function :
    <button onClick={handleClick}>
    Click
    </button>

Passing arguments :

    If you need to pass an argument, use an arrow function:

    function App() {
    function greet(name) {
        console.log("Hello " + name);
    }

    return (
        <button onClick={() => greet("Aswathi")}>
        Click
        </button>
    );
    }

    Here:

    Click
    ↓
    Arrow function
    ↓
    greet("Aswathi")

Event object :

    React passes an event object to the handler.

    function App() {
    function handleClick(event) {
        console.log(event);
    }

    return <button onClick={handleClick}>Click</button>;
    }

    You can use it to get information about the event.

    For an input:

    function App() {
    function handleChange(event) {
        console.log(event.target.value);
    }

    return <input onChange={handleChange} />;
    }

    If you type:

    Hello

    the value can be accessed through:

    event.target.value

preventDefault() :

    Some browser actions have a default behavior.

    For example, submitting a form normally reloads/navigates the page.

    React can prevent that:

    function App() {
    function handleSubmit(event) {
        event.preventDefault();
        console.log("Form submitted");
    }

    return (
        <form onSubmit={handleSubmit}>
        <button type="submit">Submit</button>
        </form>
    );
    }

    preventDefault() means:

    Stop the browser's default action.


React Fragments :
    A React Fragment is used to group multiple elements without adding an extra DOM element 
    to the actual HTML structure. Fragments are useful when a component needs to return Multiple
    elements but we don't want an unnecessary wrapper such as a <div>. 
    They can be written using <React.Fragment> or the shorthand <>...</>.

Children Prop :
    The children prop is a special prop in React that represents the content placed between
    the opening and closing tags of a component. It allows a component to receive and render nested 
    elements or components without explicitly defining them as a separate prop.

    Suppose we create:

    function Card({ children }) {
    return (
        <div>
        {children}
        </div>
    );
    }

    Now we can use:

    <Card>
    <h1>Hello Aswathi</h1>
    <p>Welcome</p>
    </Card>

    Everything between:

    <Card>
    ...
    </Card>

    becomes the children prop.

    So:

    <Card>
    <h1>Hello</h1>
    <p>Welcome</p>
    </Card>

            ↓

    children
    ↓
    <h1>Hello</h1>
    <p>Welcome</p>
    children = content passed between a component's opening and closing tags.

Default Props :
    Default props are fallback values used when a component does not receive a 
    particular prop from its parent. They allow a component to have a default 
    value instead of receiving undefined. In modern functional components, 
    default values are commonly provided through JavaScript parameter destructuring.

Suppose:

    function User({ name }) {
    return <h1>Hello {name}</h1>;
    }

    If we use:

    <User />

    name is undefined.

    We can provide a default:

    function User({ name = "Guest" }) {
    return <h1>Hello {name}</h1>;
    }

    Now:

    <User />

    gives:

    Hello Guest

    But:

    <User name="Aswathi" />

    gives:

    Hello Aswathi

    So:

    Prop provided
        ↓
    Use provided value

    Prop not provided
        ↓
    Use default value
    Default Props = fallback values used when a prop isn't provided.

Prop Drilling :
    Prop drilling is the process of passing data through multiple intermediate 
    components using props, even when those intermediate components do not need the 
    data themselves, just so that a deeply nested component can receive it. It can make component 
    communication harder to maintain, especially in large component trees. Context API or other state-management 
    solutions can be used when appropriate to avoid unnecessary prop passing.

    Imagine this component structure:

    App
    ↓
    Dashboard
    ↓
    Profile
    ↓
    User

    Suppose App has:

    const username = "Aswathi";

    But User needs the username.

    You might do:

    function App() {
    const username = "Aswathi";

    return <Dashboard username={username} />;
    }

    Then:

    function Dashboard({ username }) {
    return <Profile username={username} />;
    }

    Then:

    function Profile({ username }) {
    return <User username={username} />;
    }

    Finally:

    function User({ username }) {
    return <h1>{username}</h1>;
    }

    Notice:

    App
    ↓ username
    Dashboard
    ↓ username
    Profile
    ↓ username
    User

    Dashboard and Profile don't actually need the username. They are just passing it through.

    That's prop drilling.


Why can prop drilling be a problem?:

    Imagine:

    App
    ↓
    A
    ↓
    B
    ↓
    C
    ↓
    D
    ↓
    E

    If E needs some data from App, you may have to pass that prop through:

    App → A → B → C → D → E

    As the application grows, this can become difficult to maintain.

    Common solution

    For shared data across many levels, React's Context API can sometimes avoid this:

            Context
        ↙      ↘
    Component  Component

    Instead of manually passing the prop through every intermediate component.
